# پشتیبانی Aether 2.4 در زیرگذر

مرجع این راهنما انتشار [Aether v2.4.0](https://github.com/CluvexStudio/Aether/releases/tag/v2.4.0)
و راهنمای خط فرمان همان نسخه است.

## تغییرات هسته

نسخهٔ ۲٫۴ ثبت حساب را با API جدید Cloudflare انجام می‌دهد و در صورت نیاز
به نام قدیمی و آدرس‌های جایگزین برمی‌گردد. حساب موجود را نگه می‌دارد و فعال‌سازی
WARP را هنگام ساخت حساب انجام می‌دهد. نام TLS پیش‌فرض MASQUE اکنون
`www.cloudflare.com` است. اسکن و انتخاب مجدد درگاه پس از قطع‌های پی‌درپی
اصلاح شده و حالت‌های چندمرحله‌ای، ثبت حساب و حمل اتصال از طریق تور و سایفون
بهبود یافته‌اند. درگاه‌های محلی از آغاز اجرای فرایند رزرو می‌شوند؛ بازبودن پورت
به‌تنهایی نشانهٔ آماده‌بودن تونل نیست.

API اکنون `--api-address`، `--api-host` و `--api-sni` دارد. گزینهٔ fragment
به درخواست‌های ساخت حساب هم اعمال می‌شود. نام قدیمی `--enroll-address` و
کلید `--no-fragment` در نسخهٔ جدید حذف شده‌اند. زیرگذر نام گزینهٔ آدرس API
را از قابلیت‌های هسته تشخیص می‌دهد و گزینهٔ حذف‌شده را به آن نمی‌فرستد.

این اصلاحات داخلی با نصب خود هستهٔ ۲٫۴ فعال می‌شوند. زیرگذر دوباره آن‌ها را
پیاده‌سازی نمی‌کند.

## تنظیمات در زیرگذر

در صفحهٔ کانفیگ، Aether را انتخاب و «گزینه‌های پیشرفته اتر» را باز کنید.
مقدار خالی یعنی رفتار پیش‌فرض هسته. گزینه‌های زمانی بر حسب ثانیه‌اند؛
مهلت خواندن نام سرور بر حسب میلی‌ثانیه است.

| گروه | امکانات |
|---|---|
| اتصال | WireGuard، MASQUE، WireGuard روی MASQUE، Gool کلاسیک، MASQUE دوبل؛ HTTP/2 و HTTP/3؛ اسکن verified؛ آدرس مستقل HTTP/2؛ QUIC v2؛ اتصال مجدد سریع |
| زمان‌بندی | مهلت راه‌اندازی و اعتبارسنجی، فاصله اتصال مجدد، بررسی کشور خروجی، زنده‌نگه‌داشتن TCP و HTTP/2 و WireGuard، زمان کنارگذاشتن درگاه ناموفق |
| API حساب | آدرس اتصال، Host و SNI مستقل، ECH و DNS مخصوص ساخت حساب؛ تنظیمات TLS و fragment در ثبت حساب هم استفاده می‌شوند |
| TLS | رمزنگاری‌های TLS 1.2 و 1.3، گروه‌ها و key share، امضا، GREASE، فشرده‌سازی گواهی، ALPS، مراجع اعتماد و پدینگ، OCSP، SCT، تیکت نشست و ترتیب افزونه‌ها |
| ECH | خودکار یا کلید دلخواه، resolver و دامنه دلخواه، GREASE ECH |
| Zero Trust | نام تیم، شناسه و رمز service token یا enrollment token، درگاه سازمان و بررسی گواهی MASQUE |
| تور و سایفون | حالت مستقل، داخل تونل و حامل تونل، پل‌های تور و فایل پل، تعداد و پورت رله‌ها، تنظیمات و فهرست سرور سایفون، کشور خروجی و فهرست‌های CDN |
| مسیریابی | مسدودسازی و عبور مستقیم بر اساس قواعد Aether یا فایل؛ کنترل خواندن نام سرور |
| منابع و گزارش | پروفایل کم/متوسط/زیاد، تعداد کلاینت‌ها، سطح گزارش، آمار و فاصله ثبت آمار |

فایل‌های اختیاری باید از قبل زیر `/etc/zirgozar` موجود باشند. مقدارهایی مانند
`../` پذیرفته نمی‌شوند. قوانین ترافیک روتر قبل از قوانین داخلی Aether اعمال می‌شوند؛
قانون direct در Aether مقصد را از تونل آن خارج می‌کند.

در ثبت حساب Gool کلاسیک و MASQUE دوبل، هر دو حساب بررسی و در صورت نیاز
ساخته می‌شوند. حساب‌های تیم Zero Trust نیز با نام فایل مخصوص همان تیم بررسی
می‌شوند؛ حساب عمومی با حساب تیم اشتباه گرفته نمی‌شود. کلید داخلی Gool جدید
را خود هسته از داخل تونل می‌سازد.

نام میزبان و SNI مربوط به API معمولاً باید یکسان باشند؛ Cloudflare ممکن است
در صورت اختلاف آن‌ها خطای ۴۰۳ برگرداند. انتخاب gateway سازمان، فیلتر و ثبت
گزارش آن سازمان را نیز فعال می‌کند. GREASE ECH به‌تنهایی رمزگذاری ECH نیست.

زیرگذر پورت‌های داخلی SOCKS، علامت فایروال، مسیر حساب‌ها، مسیر برنامه‌های
همراه و سرویس راه‌اندازی را مدیریت می‌کند. این گزینه‌ها به‌صورت متن فرمان آزاد
در لینک وارد نمی‌شوند. ورود Zero Trust با ایمیل و دریافت کد تعاملی، گردش کار
پنل نیست؛ از service token، enrollment token یا حساب از قبل ثبت‌شده استفاده کنید.

لینک‌های `aether://` گزینه‌های پیشرفته را هنگام واردکردن، ویرایش و خروجی‌گرفتن
حفظ می‌کنند. واردکردن JSON دارای `aetherCommand` نیز گزینه‌های شناخته‌شده را
به داده تبدیل می‌کند؛ متن فرمان هرگز توسط shell اجرا نمی‌شود و اتصال upstream
تنها وقتی بازسازی می‌شود که قواعد SOCKS محلی آن بدون ابهام باشند.

## بررسی

تست‌ها انتقال گزینه‌ها از لینک تا آرگومان و محیط فرایند، حفظ تنظیمات در فرم،
ثبت حساب‌های دوبل و ردکردن مقدارهای نامعتبر را بررسی می‌کنند. تنظیم دلخواه TLS
باید توسط BoringSSL هسته پشتیبانی شود؛ قبول‌شدن فرم تضمین دسترسی شبکه یا
وجود کشور خروجی درخواستی نیست.
